# Knowloop 제품 개요

## 1. 서비스명

### 프로젝트명
Knowloop

### 국문
배움이 휘발되지 않도록, 교육의 맥락을 기억하는 AI Memory OS

### 영문
Edu Memory OS

### 서비스 한 줄 소개
학생의 AI 학습 대화와 교육 현장의 자료를 지속적으로 축적·구조화하여, 휘발되는 학습을 누적 자산으로 바꾸고 교강사와 교육 운영자의 개입까지 고도화하는 차세대 교육 AI 솔루션

참고:
- 이 문서는 Knowloop의 전체 제품 비전을 설명한다.
- 현재 구현 범위와 제외 범위는 `docs/product/mvp-scope.md`를 기준으로 판단한다.

## 2. 기획 배경

AI는 이미 교육 현장에서 널리 사용되고 있다. 학생들은 ChatGPT, Claude, Copilot 등 다양한 생성형 AI를 활용해 문제를 풀이하고 개념을 질문하며 스스로 학습하고 있다. 교강사 역시 수업자료 제작, 문제 출제, 요약, 피드백 초안 작성 등에 AI를 사용하기 시작했다. 그러나 현재의 AI 활용은 대부분 `그 순간의 답변`에 머무르고 있으며, 학습과 수업 과정에서 발생한 맥락은 체계적으로 축적되지 못하고 있다.

교육 현장에는 다음과 같은 문제가 반복된다.

- 학생은 AI와 수많은 질문응답을 주고받지만, 그 내용이 채팅창에 남을 뿐 자기 지식으로 정리되지 않아 같은 질문을 반복한다.
- 교강사는 학생이 어디서 막혔는지, 어떤 개념에서 반복적으로 흔들리는지 늦게 알게 된다.
- 운영자는 공지, 문의, 상담, 규정 해석이 여러 채널에 흩어져 있어 같은 설명을 반복하게 된다.
- 기존 LMS는 자료를 저장하는 데는 유용하지만, 교육 과정에서 형성되는 의미 있는 맥락을 누적 자산으로 바꾸는 데는 한계가 있다.

즉, 지금 교육 현장에서 가장 크게 낭비되는 것은 단순한 시간이 아니라 `맥락의 휘발`이다. 본 서비스는 이 문제를 해결하기 위해 기획되었다.

## 3. 문제 정의

### 3.1 수강생 관점

- AI에게 많이 질문하지만 배움이 정리되지 않는다.
- 이전에 무엇을 물었고 무엇을 이해하지 못했는지 스스로 파악하기 어렵다.
- 같은 질문을 반복하며 학습 효율이 떨어진다.
- 일반 AI는 개인의 이전 학습 맥락이나 수업 맥락을 충분히 반영하지 못한다.

### 3.2 교강사 관점

- 학생들의 반복 질문에 계속 같은 설명을 하게 된다.
- 어느 개념에서 학생들이 집단적으로 막히는지 실시간으로 보기 어렵다.
- 수업자료, 질문응답, 과제 결과가 연결되지 않아 정밀한 수업 개입이 어렵다.
- 강사의 설명 노하우가 사람 머릿속이나 메신저 대화에만 남고 자산화되지 않는다.

### 3.3 교육 운영자 관점

- 공지, 규정, 운영 안내가 여러 채널에 분산되어 있다.
- 동일한 문의와 민원이 반복 발생한다.
- 담당자가 바뀌면 운영 지식이 이어지지 않는다.
- 정보 충돌이나 누락을 늦게 발견하게 된다.

## 4. 해결 방안

본 서비스는 교육 현장의 데이터를 AI가 자동으로 분석·구조화하여 `지속적으로 갱신되는 교육 위키와 학습 메모리 레이어`를 구축하는 솔루션이다.

Knowloop는 전통적인 벡터 RAG 중심 챗봇이 아니라,
대화와 첨부자료를 바탕으로 지속적으로 wiki를 작성·갱신하고 그 wiki를 주요 지식원으로 참조하는 `LLM-Wiki 기반 Edu Memory OS`로 설계한다.

핵심 개념은 다음과 같다.

- 강의자료, 학생 질문, 과제 피드백, 공지, 상담 기록 등을 `raw source`로 저장한다.
- AI가 이를 읽고 개념, 오개념, 선수지식 관계, 미해결 질문, 반복 문의 등을 구조화한다.
- 구조화된 결과는 `candidate layer`와 `formal wiki`로 나뉘어 관리된다.
- 학생에게는 개인 학습 위키와 복습 큐를 제공하고, 교강사에게는 반복 오개념과 개입 포인트를 제안하며, 운영자에게는 공지/FAQ/문의 패턴을 정리해준다.

즉, 본 서비스는 질문에 답변하는 AI를 넘어서, 교육 현장의 경험과 상호작용을 `재사용 가능한 지식 자산`으로 축적하는 AI 기반 Memory OS이다.

## 5. 서비스 목표

### 목표 1. 학생의 휘발성 학습을 누적 자산으로 전환

- AI와 나눈 질문응답을 자동으로 구조화
- 개인 학습 위키 생성
- 약점 개념과 미해결 질문 추적
- 복습 및 회상 중심 후속 학습 지원

### 목표 2. 교강사의 반복 설명 부담 감소

- 반 전체 반복 질문 자동 집계
- 오개념 히트맵 제공
- 보충설명과 FAQ 초안 생성
- 다음 수업 개입 포인트 제안

### 목표 3. 교육 운영 지식의 축적 및 재사용

- 운영 문의와 공지를 구조화
- 자주 반복되는 FAQ 자동 정리
- 공지 충돌 및 누락 탐지
- 담당자 변경 이후에도 운영 지식 유지

## 6. 핵심 서비스 구조

### 6.1 Raw Source Layer

수집 대상:
- 강의자료
- 학생 질문 및 AI 대화
- 과제/시험 결과
- 과제 피드백
- 공지사항
- 상담 및 운영 메모

역할:
- 원본 보존
- 출처 추적
- 정식 위키의 근거 자료 역할

### 6.2 Session Memory Layer

수집 대상:
- 학생-AI 대화
- 교강사-AI 대화
- 운영자-AI 대화

역할:
- 최근 대화 맥락 기억
- 이전 질문 검색
- formal wiki로 승격되기 전의 중간 기억 저장소

### 6.3 Candidate Layer

저장 대상:
- 잠정 오개념
- 미해결 질문
- 반복 질문 후보
- 교강사 개입 가설
- 운영 FAQ 후보

역할:
- 미완성 지식을 바로 정식 위키로 올리지 않고 검토 가능 상태로 유지
- 위키 오염 방지

### 6.4 Formal Wiki Layer

저장 대상:
- 과목 개념 페이지
- 선수지식 페이지
- 오개념 페이지
- FAQ
- 주차별 요약
- 반별 인사이트
- 운영 규정 및 해설

역할:
- 역할별 AI 에이전트의 주요 참조 지식층
- 시간이 지날수록 더 정교해지는 축적 자산

### 6.5 Learning Layer

아래 항목은 전체 제품 관점의 저장 대상 예시이며, 현재 MVP의 최소 범위는 `docs/product/mvp-scope.md`를 우선 기준으로 본다.

저장 대상:
- 학생별 약점 개념
- review queue
- flashcards
- gap tracker
- 회상 질문

역할:
- 자동 정리를 실제 학습 효과로 연결
- 학습자의 자기주도 복습 지원

## 7. 주요 기능

## 7.1 수강생용 기능

### 1) AI 학습 대화 자동 축적
- 학생이 AI에게 한 질문과 답변을 자동 저장
- 과거 질문 검색 가능
- 같은 질문 반복 여부 표시

### 2) 개인 학습 위키 자동 생성
- 질문과 답변을 그대로 저장하는 것이 아니라,
  개념, 헷갈린 이유, 관련 개념, 출처, 복습 포인트 중심으로 정리

### 3) 약점 개념 분석
- 반복 질문과 오답 패턴을 바탕으로 학생의 취약 개념 추출
- “내가 자주 막히는 개념” 시각화

### 4) 복습 액션 추천
- 오늘 배운 내용 요약
- 미니 퀴즈 제공
- 다음에 다시 물어볼 질문 추천
- 복습 우선순위 제공

## 7.2 교강사용 기능

### 1) 반복 질문 집계
- 반 전체에서 자주 나오는 질문 자동 수집
- 단원별 반복 질문 분류

### 2) 오개념 히트맵
- 학생들이 어느 개념에서 가장 많이 흔들리는지 시각화
- 선수지식 부족과 현재 개념의 연결 파악

### 3) 개입 포인트 추천
- 다음 수업 시작 전에 보충해야 할 포인트 제안
- 추가 설명 자료 또는 공지 초안 생성

### 4) FAQ / 보충자료 자동 초안
- 반복되는 질문을 바탕으로 공지 초안, FAQ, 보충설명 문서 생성

## 7.3 교육 운영자용 기능

### 1) 운영 FAQ 자동 정리
- 반복 문의를 FAQ 후보로 구조화

### 2) 공지 충돌 탐지
- 서로 다른 공지 간 내용 충돌 여부 탐지

### 3) 운영 지식 축적
- 상담, 운영 메모, 안내 기준을 지속형 운영 위키로 축적

## 8. 차별성

### 차별성 1. 답변형 AI가 아니라 축적형 AI

기존 교육 AI는 대부분 질문에 답하는 데 집중한다. 그러나 본 서비스는 답변을 넘어서, 질문과 자료, 피드백이 `다음 답변과 다음 수업에 반영되는 구조`를 만든다.

### 차별성 2. 학생·교강사·운영자를 동시에 연결하는 메모리 구조

대부분의 솔루션은 학생용 튜터, 교사용 도우미, 운영용 도구가 분리되어 있다. 본 서비스는 하나의 Memory Layer 위에서 각 역할에 맞는 에이전트가 동작하도록 설계한다.

### 차별성 3. Candidate Layer를 통한 지식 품질 관리

모든 질문과 답변을 곧바로 정식 위키로 올리지 않고, 후보 단계에서 검토·승격·병합하는 구조를 둔다. 이를 통해 잘못된 정보 누적을 방지한다.

### 차별성 4. Learning Layer를 통한 실제 학습 성과 연결

자동 정리만으로는 학습이 일어나지 않는다. 본 서비스는 gap tracking, flashcards, 회상 질문, review queue를 통해 정리된 내용을 실제 이해와 기억으로 연결한다.

## 9. 시스템 구현 방향

## 9.1 MVP 구현 방식

- Frontend: React 또는 Next.js 기반 웹앱
- Backend: Python FastAPI 또는 Node.js
- Storage:
  - Markdown 기반 wiki 파일
  - SQLite
  - FTS5 검색
- LLM 처리:
  - source ingest
  - candidate 생성
  - formal wiki 업데이트
  - learning layer 생성

## 9.2 데이터 흐름

1. 강의자료/학생질문/공지 등 원본 데이터 수집
2. AI가 source type을 분류
3. candidate item 생성
4. 검토 후 formal wiki 반영
5. 학생 개인 learning layer 업데이트
6. 교강사용 인사이트와 운영 FAQ 후보 생성

## 9.3 참고한 구현 패턴

- `Atomic Knowledge`: candidate lifecycle
- `Sage Wiki`: compile/query/lint 구조
- `Memex`: audit/queue 구조
- `LLM Knowledge Base`: learning layer
- `LLM Wiki Template`: session memory 검색
- `Mnemon`: 개인화 추출

## 10. 사용자 시나리오

### 시나리오 1. 수강생

학생 A는 AI에게 미적분 개념을 질문한다. AI는 강의자료와 학생의 이전 질문 기록을 참고해 맞춤형 답변을 제공한다. 답변 후 시스템은 해당 내용을 개인 학습 위키에 반영하고, 학생이 반복적으로 헷갈리는 개념을 gap tracker에 추가한다. 이후 학생은 “내가 자주 틀리는 개념만 다시 보기” 기능으로 복습할 수 있다.

### 시나리오 2. 교강사

교강사 B는 반 전체 대시보드에서 학생들이 특정 단원에서 반복적으로 막히는 패턴을 확인한다. 시스템은 “선수지식 부족으로 인해 현재 개념이 흔들리고 있음”을 분석해 다음 수업 시작 전 보충 설명 포인트를 추천한다. 동시에 자주 나온 질문을 바탕으로 FAQ 초안을 자동 생성한다.

### 시나리오 3. 운영자

운영자 C는 학생 문의 내역을 확인한다. 시스템은 최근 반복 문의된 내용을 분석해 운영 FAQ 후보를 제안하고, 기존 공지와 충돌하는 안내가 있는 경우 이를 탐지해 표시한다.

## 11. 기대 효과

### 11.1 수강생 측면

- AI 학습 대화가 휘발되지 않고 축적된다.
- 반복 질문이 줄어든다.
- 개인 약점 개념을 명확히 파악할 수 있다.
- 복습 효율이 높아진다.

### 11.2 교강사 측면

- 반복 설명에 소모되는 시간을 줄일 수 있다.
- 학생 집단의 막힘 지점을 빠르게 파악할 수 있다.
- 보다 정교한 개입과 수업 설계가 가능해진다.
- 자신의 설명 노하우를 자산화할 수 있다.

### 11.3 운영 측면

- 반복 문의 대응 비용이 줄어든다.
- 운영 지식이 누적되어 담당자 변경에도 유지된다.
- 공지/규정 충돌을 미리 탐지할 수 있다.

### 11.4 기관 전체 측면

- 시간이 지날수록 해당 기관에 맞춤화된 교육 Memory OS가 형성된다.
- 단순한 AI 활용을 넘어, 교육 현장의 지식 운영 체계가 고도화된다.

## 14. 결론

본 서비스는 단순히 질문에 답하는 교육 AI가 아니다. 교육 현장에서 발생하는 자료, 질문, 피드백, 공지, 상담 등의 맥락을 구조화하고 축적하여, 학생에게는 배움이 남게 하고, 교강사에게는 개입 포인트를 제공하며, 운영자에게는 지식이 정리되도록 만드는 `교육용 AI Memory OS`이다.

즉, 본 기획의 핵심은 다음 한 문장으로 정리할 수 있다.

`우리는 답변을 생성하는 AI를 만드는 것이 아니라, 교육 현장의 배움과 운영의 맥락이 사라지지 않도록 축적하는 AI를 만든다.`
